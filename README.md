# Alliance Dance Studio

A Vite/React site with an Express + tRPC backend, PostgreSQL/Drizzle persistence, Manus OAuth administration, and Stripe-hosted Checkout for studio reservations.

## Reservation lifecycle

1. The browser requests active studios plus anonymous opening/busy intervals.
2. The server validates Toronto-local date/time and calculates price from database rates.
3. A PostgreSQL transaction takes sorted per-studio/date advisory locks, rechecks overlap, and writes a short-lived hold.
4. The customer pays on Stripe-hosted Checkout.
5. A signed Stripe webhook retrieves the Checkout Session and verifies its reservation ID, amount, and currency before confirming all associated booking rows.
6. Paid bookings and active holds are returned as busy intervals, so overlapping times are disabled in the UI.

The success page performs the same idempotent verification for immediate feedback. It supplements rather than replaces the webhook.

## Apply and install

This delivery is an overlay, not a complete clone. Apply it to a clean checkout:

```bash
/path/to/alliance-dance-studio-stripe/apply-overlay.sh /path/to/alliance-dance-studio
cd /path/to/alliance-dance-studio
pnpm install --no-frozen-lockfile
```

`package.json` is intentionally pruned and `package-lock.json` is removed so pnpm is the single package manager. The existing `pnpm-lock.yaml` must be regenerated by the install command and committed with the code changes.

Then configure the environment, migrate a backed-up development database, and run:

```bash
cp .env.example .env
psql "$DATABASE_URL" -f drizzle/migrations/0001_stripe_reservations.sql
pnpm db:seed       # optional; replaces availability for Studio 5/6/7
pnpm check
pnpm test
pnpm build
pnpm dev
```

For a disposable database, `pnpm db:push` can reconcile the schema instead of applying the SQL migration manually.

## Local Stripe webhook

```bash
stripe listen --forward-to localhost:3000/api/stripe/webhook
```

Put the CLI-provided signing secret in `STRIPE_WEBHOOK_SECRET`, restart the fixed-port development server, and follow `STRIPE_TESTING.md`.

## Security requirements

Never commit `.env` or expose `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET`, `JWT_SECRET`, or `DATABASE_URL` to browser code. Keep `STRIPE_TEST_MODE_ONLY=true` until a separately reviewed live launch. Production requires an HTTPS `APP_URL`; configure `TRUST_PROXY_HOPS` only for a known proxy topology.

See `SECURITY_REVIEW.md` for the addressed findings and remaining launch work.
